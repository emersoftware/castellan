# Wizard source art

Source images for the [Wizard](../../docs/wizard-plan.md). The five `grayscale/idle_*.png`
views are registered unchanged as the game's `assets/sprites/wizard_0..4` stills; the
rest stay reference art. Each action is one static
reference pose in five views, **not** a finished animation or gameplay proof.
The [MiniMax animation pass](../animations/wizard/README.md) now has all five
actions in eight directions, with dithered previews in all four player colours.

The requested design is a simple faceless figure: one continuous pointed hood
and robe, no visible beard, hair or face, no embroidered costume or separate
hat brim. A plain staff and small crystal preserve the wizard silhouette.

## Files

- `source/`: original transparent ImageGen outputs, preserved before filtering.
  Five turnarounds (`idle`, `walk`, `heal`, `hack`, `death`) and two ability icons.
- `prompts.json`: exact accepted-source generation prompts and tool provenance.
- `grayscale/`: 25 poses in S, SE, E, NE, N order, plus two ability icons.
- `dithered/teamA` through `teamD`: the same poses and icons in the real player
  ramps, plus a full-body SE portrait copied from the idle pose.
- `contact-sheet.png`: all actions and icons in all four player ramps.
- `turnarounds.png`: all 25 poses in team A, for direction and clipping review.
- `game-scale.png`: previews dithered after downsampling to normal game scale.
- `manifest.json`: original candidate geometry, source bounding boxes and mirror
  mapping, as recorded before registration.
- `validation.json`: transparency and palette checks for the 100 tinted poses.

## Reproduce the filtering

From the repository root:

```sh
node --import tsx assets/wizard/render.mts
```

The renderer imports the actual `normalizeCharacterContrast`, `ditherPixels`
and `PLAYER_RAMPS` from `packages/web/src/render`. It measures each complete
turnaround once to avoid contrast shifts between directions, then applies
Bayer 4x4 three-tone dithering. No filter is approximated or generated by AI.
Grayscale source cells remain unnormalized for future runtime processing.

Standing cells are 112 x 112, death cells 112 x 119, stored scale 3 and ground
anchor at `(56, 101.5)`, following the existing animation layout. Standing
turnarounds use at most 87 stored pixels of height. The corpse uses a wider
footprint fitted within the cell; review its scale again when animating.
Every view of an action shares one scale. SW, W and NW mirror SE, E and NE.

Exported sprites dither at stored resolution (maximum normal camera zoom).
The game-scale sheet instead downsamples before dithering, because the game's
shader dithers screen pixels. Ability icons use the portrait renderer's 1.1
lift. Exported colours preserve owner identity; healing and hacking differ by
curved versus angular shapes rather than inventing additional team colours.

Healing/hacking energy in the pose sheets is art reference, not evidence of a
successful action. Final channels, beams and target overlays should be separate
renderer effects driven by authoritative state. The current full-body portrait
matches the game's still-portrait convention; no separate face was invented.

Made using the built-in ImageGen tool on 2026-10-23. Earlier bearded/ornate
explorations were superseded by the user's simpler faceless direction; they
remain outside this checkout in the local Castellan art archive. No paid model
matches, animation API, deployment, commit or push were used for the static art
pass. The subsequent animation pass uses MiniMax H3 Turbo as documented above.
